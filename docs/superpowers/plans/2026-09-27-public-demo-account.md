# 공용 데모 계정 — 2026-09-27

사용자 요청: 로그인·회원가입 화면에서 지정한 공용 데모 계정으로 실제 체험할 수 있도록 한다. 계정 정보는 공개 안내용으로 사용자가 직접 지정했다.

## 결과와 범위

- 일반 회원인 데모 계정을 별도 운영 명령으로 생성한다. 관리자 생성 경로는 사용하지 않는다.
- 일반 신규 비밀번호의 15자 정책은 유지한다. 지정된 공개 데모 비밀번호만 신뢰된 생성 경로에서 해시한다.
- 기존 이메일·관리자 identity와 충돌하면 덮어쓰지 않는다. 멱등 재실행은 같은 데모 계정임을 확인한 경우만 허용한다.
- 이메일만으로 기존 계정을 데모로 분류하지 않는다. `Member.is_demo` 기본값 false와 기존 멱등 컬럼 추가 절차를 사용해 운영 명령으로 생성한 계정만 표시한다.
- 계정이 실제 준비된 경우에만 로그인·회원가입 화면에 안내와 사용 버튼을 보여준다. 공개 가입 차단은 유지한다.
- 공용 데모의 비밀번호 변경·재설정·탈퇴·전체 강제 로그아웃·API 키 발급/접근·실계좌 연결을 서버에서 차단한다. 현재 세션 로그아웃과 모의 체험은 허용한다.
- 보호는 프로필에 관계없이 적용한다. 로컬 검증에서도 같은 계정을 생성해 보호 경로를 검증할 수 있어야 한다.
- 모의 거래·메모가 공용으로 공유됨을 안내한다. 세션별 별도 계정, 데이터 초기화 예약, 새 권한 프레임워크는 추가하지 않는다.

## 구현과 검증

1. 기존 계정 helper·해시·CLI·프런트 안내 패턴을 재사용한다. 불필요한 스키마 변경이나 의존성 추가를 피한다.
2. 서버 보호 경로와 일반 계정 회귀·생성 충돌을 테스트한다. 재설정 요청의 기존 계정 존재 여부 은닉 응답을 유지한다.
3. 독립 소스 리뷰를 받고 `stockdesk-verify`에서 준비 전후 안내, 데모 로그인·로그아웃, 계정 변경 차단, 390px 화면을 실제 주행한다.
4. 공개 사이트 반영 여부는 로컬 구현·검증 결과와 별도 기록한다. 실제 생성·배포 없이 공개 사용 가능이라고 보고하지 않는다.
